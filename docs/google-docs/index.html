Google Docs

Offizin for Google Docs

Offizin for Google Docs is a small Apps Script project that lives inside a document. Once it is in a document, an Offizin menu opens the same panel you can try in the live demo. It works with personal Google accounts and with Google Workspace for business, school, and nonprofits.

The quick way: copy the starter document

  1. Select the button below and choose Make a copy. Offizin comes with the copy.
  2. In your copy, choose Offizin, then Open Offizin, and allow access when Google asks (see permissions). Every copy asks the first time Offizin opens in it.
  3. Keep that copy as your starter. Each time you need a new publication, make a copy of it. Your design and business details stay with the document you entered them in, so save a brand kit once on the Info tab and open it in each copy.

offizin-google-docs.zip

  1. Open the Google Doc you want to use, or a new one at docs.new. If it is a pageless document, choose File, Page setup, then Pages.
  2. Choose Extensions, then Apps Script. A code editor opens in a new tab. Click Untitled project at the top and rename it Offizin.
  3. In Code.gs, select everything and replace it with Offizin's code:
    Code.gs The menu and the part that builds publicationsDownload
  4. Next to Files, select +, then HTML. Name it Sidebar exactly (Apps Script adds .html). Replace everything in it with:
    Sidebar.html The Offizin panelDownload
  5. Open Project Settings (the gear icon) and check Show "appsscript.json" manifest file in editor. Go back to the Editor (the code icon), open appsscript.json, and replace everything in it with:
    appsscript.json Asks only for access to this documentDownload
  6. Save with Ctrl S (or Command S), close the Apps Script tab, and reload your document.

Permissions and the "unverified app" screen

Offizin asks for two permissions, the narrowest Google offers:

  • View and manage documents that this application has been installed in. Offizin can only change the document it is in. It cannot see your other files.
  • Display and run third-party web content in prompts and sidebars. This is what lets the Offizin panel open beside your document.

Because you pasted the code yourself, it runs as your own private script, and Google has not reviewed it. With a personal Gmail account, Google shows Google hasn't verified this app. Select Advanced, then Go to Offizin (unsafe), then allow access. If Google lists the two permissions with checkboxes, check both (or Select all) before you continue: without the first, Offizin cannot change the document, and without the second, the panel cannot open. The wording is Google's standard text for any script that is not published in its Marketplace. In a Google Workspace organization, people in the same organization as the document's owner usually see the normal permission screen. Each copy of a document is its own script, so each copy asks the first time Offizin opens in it.

For Google Workspace organizations

Share a starter document

Set up one Offizin starter document, share it with your organization as view only, and ask people to make a copy. Each copy carries Offizin. Each copy is its own script, so Google asks each person for permission the first time Offizin opens in each copy, and settings stay with the copy they were entered in; a brand kit carries them from one copy to the next.

Publish privately to your domain

An administrator can publish Offizin as a private add-on through the Google Workspace Marketplace SDK, so it appears in every document under Extensions. It is one script, so people approve it once and their saved details follow them from document to document. This needs a Google Cloud project; see Help for the steps.

For IT teams: upload with clasp

Google's command line tool, clasp, uploads the package's files in one step. Turn on the Google Apps Script API at script.google.com/home/usersettings, then:

  1. Install and sign in: npm install -g @google/clasp, then clasp login.
  2. In an empty folder, run clasp create --type docs --title "Offizin starter". This makes a new Google Doc with its own Apps Script project.
  3. Copy Code.gs, Sidebar.html, and appsscript.json from the package into that folder. If clasp made a Code.js file, delete it, and let the package's appsscript.json replace the one clasp made.
  4. Run clasp push --force, then open the new document from Google Drive and reload it.

Undo and printing in Google Docs

  • Offizin's own Undo and Redo. The arrows at the top of the Offizin panel undo only what Offizin did, and leave your typing and Google Docs' own Undo alone. Undoing a page part removes it, and Redo puts it back with whatever you typed into it. Undoing a design puts the previous colors and fonts back. Undoing a new publication brings back the document as it was before, for up to six hours. The history lasts while the panel is open.
  • Printing. Google Docs does not let add-ins change print settings, so the Check tab lists the steps: two-sided printing, the right edge to flip on, and actual size. Booklets come out already arranged in printing order, two pages to a sheet.

Updating

Pasted copies of Offizin do not update themselves. When a new version is released, repeat steps 3 to 5 in your starter document (or run clasp push again). Documents copied from it afterward get the new version. The current version is 2.1.2. Version 2.1.1 gives headings a typewriter-like face. Version 2.1 adds Offizin's own Undo and Redo, Customize settings for every publication, mail merge, booklets, plain resumes and CVs, and black and white designs, so paste the three new files to get them.
